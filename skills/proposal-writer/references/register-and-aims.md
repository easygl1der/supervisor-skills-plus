## 1. Proposal register versus paper register

| Aspect | Paper | Proposal |
|---|---|---|
| Tense | Past for what was done, present for what holds | Future for planned work; past for preliminary results; present for the state of the art |
| Core move | Report and interpret findings | Commit to work and show it can be done |
| Evidence | Results of this study | Cited work, preliminary data, secured resources |
| Claims about results | Scoped to what was measured | Expected outcomes, hedged, never written as found |
| Reader | Specialist referee, reads in full | Panel, partly non-specialist, often skims the first page |
| Risk | Threats to validity, after the fact | Risks and fallbacks, before the fact |
| Structure | Fixed by venue convention | Fixed by the call's template and criteria |
| Contribution | Demonstrated | Promised, each tied to a deliverable |

The research-core rules on claim strength still apply: a planned analysis
is never described with result words, and an expected effect is never
written with a number the user has not measured.

## 2. Sentence patterns

Commitment: "Aim 2 will estimate ..., using ..., and will release ... by
month 18." Name the object, the method and the deliverable.

Hypothesis: "We hypothesize that ... ; if so, ... will be observed;
otherwise ... ." A hypothesis states what would refute it.

Preliminary result: "In a pilot on <scope>, <measure> was <value>
(<source>), which indicates that <step> is feasible." Feasibility, not a
finding about the question.

Expected outcome: "We expect ... because ... ; if instead ..., the result
will still show ... ." Pairs the expectation with the fallback value.

Gap: "Existing methods for X assume Y (<cite>, <section>); settings
where Y fails, such as Z, are not covered by the works retrieved in
<searches>." Scoped to the evidence.

Avoid in a proposal: "will prove", "will solve", "revolutionary",
"the first" without retrieval, "we will try to", "explore" as the main
verb of an aim, and lists of activities in place of aims. Chinese kaiti
sentence frames (problem first, numbered innovation points, deliverable
milestones) are in zh-kaiti-register.md.

## 3. The one-page summary pattern

The NIH Specific Aims layout works as the first page of most proposals:
[src: guide:https://www.casrai.org/guides/nih-specific-aims-page@2026-10-16] (candidate)

1. Hook: the problem and why it matters, in two or three sentences.
2. Known and missing: what the field has, the specific gap, and the cost
   of leaving it open.
3. Long-term goal, the objective of this proposal, and the central
   hypothesis or question.
4. Aims: two to four, each a one-line heading plus two or three lines of
   approach and expected outcome.
5. Payoff: what will exist at the end and what it enables.

For a kaiti report this becomes the abstract or the opening of the
research-content section; for an ERC application it is the backbone of
the synopsis.

## 4. Designing aims

- **Related but independent.** All aims serve the central question; none
  needs another's success to deliver. A failed Aim 1 must not stop Aim 2.
  [src: guide:https://pmc.ncbi.nlm.nih.gov/articles/PMC8344099@2026-10-16; guide:https://poorvucenter.yale.edu/media/621/download@2026-10-16] (candidate)
- **Dependencies inside, not between.** Sequential steps (collect, then
  estimate, then evaluate) belong inside one aim. Between aims, a
  progressive chain is a risk; when it cannot be avoided, give the later
  aim a fallback input (public data, simulated data, a simpler version of
  the upstream output).
- **Two to four aims.** Fewer reads as thin; more reads as overreach for
  most durations. A thesis proposal often maps one research content to
  one chapter and one paper.
- **Each aim has a type**: a hypothesis to test, a question to answer, a
  method or tool to build and validate, or a resource to create. The type
  decides the success criterion.
- **Each aim is checkable**: deliverable, milestone, criterion, fallback,
  as in the timeline file.

Cascade test: for each aim, assume every other aim failed. Does this aim
still produce its deliverable? If not, add the fallback or restructure.

## 5. Gap statements

A gap is a specific missing piece, located against named work, that
matters for a stated reason. Build it from read sources (quickread cards,
study notes, `deep-research` reports), citing section, equation or table
where the limitation is stated. Separate what the authors say about their
own limits from the applicant's judgment; label the latter. A gap found
only in model memory is not a gap; run the retrieval first.

## 6. Contributions and innovation points

One contribution per aim, each phrased as something a reviewer could check
at the end: a method with a stated property, an estimate with uncertainty
for a named population, a released dataset, a validated tool. Innovation
points (in a kaiti report or NSFC application) are the same items stated
against the nearest prior work, on one named axis each (question, setting,
method, data, evidence). Generic innovation such as "fills a gap in the
literature" or "has important theoretical and practical value" is cut.
