# sv-write-intro

Formerly `intro-drafter`. The full procedure, unchanged, is
`references/procedure.md`; load it first and follow its Step 0 and its
route table.

## Load by route

| Route | Load |
|---|---|
| Technique or new problem/setting | `procedure.md` (Core procedure), `flowchart.md`, `paper-types.md`, `running-example.md`, `contribution-patterns.md`; `worked-examples.md` when an example helps |
| Empirical (RQ-driven) | `procedure.md` (Empirical route), `empirical-intro.md` |
| Benchmark | stop: `sv-write-skeleton` benchmark route first |
| Theory, math, non-STEM | stop: `sv-write-section` |
| Outline requested explicitly | `procedure.md` (Outline mode) plus the route files |

Always load the shared evidence and delivery rules. At three or more
citations, run the verification ladder.

## Non-negotiables (from the procedure)

- No running example is invented; ask for a real one in the closing note.
- No numbers the user did not report; no placeholder tags in the prose.
- Planning (positioning, paragraph plan, alignment checks) stays internal;
  a broken chain is fixed in the plan before any prose is written.
- Delivery is the prose, its References list, and at most a three-line
  note.

## Hand-offs

- The skeleton is not settled: `sv-write-skeleton`.
- The rest of the paper or the claim ledger: `sv-write-section`.
- Stiff prose afterwards: `sv-write-polish`; AI tone: `sv-write-humanize-paper`.
- Contribution format from exemplars: `sv-write-style-apply`.
- Multi-round checks: `sv-review-loop`.
